## 改咗咩

- 新首頁直接顯示本月收支、最近交易、待跟進客戶同低存量項目；主要操作由首頁一按進入。
- 底部導覽改成首頁、客戶、記帳、庫存、更多。零售、運動、宣傳、獎賞同詳細報表仍可喺「更多」開啟。
- 全域搜尋可查客戶姓名／電話、交易、產品；搜尋前會繼續載入較舊交易紀錄。交易分頁游標已獨立於畫面上合併後嘅筆數，避免區間查詢之後漏讀舊帳。
- 「快速新增」可直接選記收入、記支出、新客戶、零售或運動套票。記帳表單會預先選好收入／支出。
- 客戶頁預設顯示全部狀態，有明顯嘅新增按鈕、結果筆數同空白提示；庫存頁加低存量篩選同結果筆數。
- 登出唔再清空整個 `localStorage`，避免誤刪裝置上嘅草稿同設定。
- 設定頁加只讀 JSON 匯出，按目前登入帳戶分頁讀取客戶、交易、庫存、收支、試堂、宣傳、套票設定等資料，並連同共用產品目錄及圖片資料下載。每張表會核對讀取筆數；如果匯出中途資料變動，唔會產生不完整檔案。
- Netlify／Vercel Deploy Preview 網址加只讀防護：允許現有帳戶登入、讀取及登出，攔截正式 Supabase 嘅寫入請求，畫面亦顯示預覽提示。
- 打開設定頁唔再自動補寫預設套票設定。

## 備份與上線關口

帳戶 JSON 匯出係方便用戶自己保存可讀取嘅業務資料，**唔等於完整專案備份**。登入密碼雜湊、Auth session、伺服器操作日誌及 Storage 物件唔會由前端匯出。完整保護需要喺正式 Supabase 專案確認 [Database Backups](https://supabase.com/docs/guides/platform/backups) 嘅可用還原點，並按需要做 [CLI logical dump](https://supabase.com/docs/reference/cli/supabase-db-dump)。Supabase 文件指出資料庫備份唔包括 Storage 物件本身，檔案要另外備份。

合併到 `main` 或部署正式站之前：

1. 由專案擁有人核實最新可用還原點，同埋喺正式站下載一次帳戶 JSON；將檔案保存在安全位置。
2. 用現有帳戶喺 Netlify／Vercel 唯讀 preview 測試舊客戶、舊交易、收支、庫存同登入。要測試新增／修改流程，仍需隔離 Supabase staging 專案；預覽版會攔截寫入正式庫嘅請求。
3. 確認後先合併／正式部署。若需要回退，回退前端 commit；今次冇資料庫 migration 要回退。
