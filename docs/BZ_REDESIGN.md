## 登入與快捷客戶流程（2026-11-15）

- 登入表單新增「記住密碼」、密碼顯示鍵、忘記密碼及註冊／電郵驗證。勾選項目保存嘅係登入 session，唔會喺 App 儲存明文密碼；密碼自動填寫由裝置密碼管理器處理。預覽版容許 Supabase Auth 註冊、驗證及重設密碼，業務資料仍然只讀。
- 新客戶先填姓名、電話、分店同試堂時間；其餘資料收埋喺「更多資料」。客戶操作加入一頁式試堂結果及續卡快捷流程，套票收入、利潤同有效期按現有設定計算。已付 $98 試堂費扣款係明確勾選項；只有交易可靠地連結到該客戶時先預設勾選，避免同名客戶造成錯帳。
- 試堂時間可由佐敦、觀塘、中環課表揀選；示範模式展示明確標示嘅樣本。即時課表接口只讀課名、教練、時段及名額，唔會向原站提交任何報名動作。開清單最多使用 60 秒快取；揀課同儲存前會用 `fresh=1` 繞過快取重新核對。課堂消失、改時間／教練或額滿時停止儲存，要求重新揀。最後報名仍由用戶喺原站自行完成，因此儲存之後如原站再改課，仍需以原站確認為準。
- 課表帳密只存喺 Netlify `BZ_TIMETABLE_USER`、`BZ_TIMETABLE_PASSWORD` Secret，冇提交入 Git 或放喺 `VITE_` 變數。2026-11-15 經用戶確認後，喺 Netlify UI 設定成只有 `deploy-preview` context 有值；正式版、branch deploy、preview server 同本機開發留空。Netlify Dev 計劃唔畀單選 `functions` scope，實際 Secret 作用範圍係 Builds、Functions、Runtime。預覽版已重新建置（deploy `6af98c94fc9259aee2e17453`）。
- 2026-11-16 用戶提供新登入資料後，原網站官方登入頁成功進入課表；以 Function 同款 HTTP 流程只讀查詢佐敦、觀塘、中環均回覆 200，當日分別有 0、4、8 堂。登入成功時原站回傳 302 跳轉課表頁，Function 已修正判斷並加入測試。兩項預覽版 Secret 已更新，正式版仍留空。
- 用 BZ 帳戶喺預覽版實際打開客戶課表時，原網站對 Netlify 登入 POST 回 `429`；之後原站官方登入頁亦明確提示「登入操作過於頻繁，請 15 分鐘後再試」。因此介面改為準確顯示暫時限制，並避免短時間內重複登入。課表請求已由預設美國東部 Function 改經新加坡 Netlify Edge Function；新加坡節點仍收到同一個 `429`，所以來源網站限制並非單靠改節點可以解除。
- Edge 課表接口會喺**該次 Deploy Preview 專屬** Netlify Blob store 保存來源網站嘅短期登入 session cookie，供同一預覽部署重用，避免每次揀日期／分店重新登入；唔保存課表密碼入 Blob。session 最多重用 6 小時，過期或來源站拒絕時會刪除。來源站回 `429` 時設 15 分鐘冷卻，期間仍可手動輸入時間。Blob store 跟部署隔離，正式站及其他部署讀唔到該預覽部署嘅 session。課堂本身仍只快取最多 60 秒；揀課及儲存前重新向原站查詢。
- Netlify 以 4 位數課表密碼掃描 Edge 打包工具下載嘅 `@types/node` 快取時出現誤報。`netlify.toml` 只喺 Deploy Preview 略過該自動生成嘅依賴路徑；原始碼、正式部署及其他檔案嘅 Secret 掃描保持啟用。
- 原站伺服器位於台灣。Netlify 新站 Function 預設 Ohio，東京／新加坡 Function 區域設定只供 Pro／Enterprise；目前項目屬 Dev 計劃，所以只改用現有方案支援嘅 Edge 執行區域。待來源站 15 分鐘登入限制解除後，仍須用已登入 BZ 帳戶喺最新預覽實際揀課，完成端到端驗證。示範模式明確標示樣本課堂，唔代表原站可報名時段。

## 備份與上線關口

帳戶 JSON 匯出係方便用戶自己保存可讀取嘅業務資料，**唔等於完整專案備份**。登入密碼雜湊、Auth session、伺服器操作日誌及 Storage 物件唔會由前端匯出。完整保護需要喺正式 Supabase 專案確認 [Database Backups](https://supabase.com/docs/guides/platform/backups) 嘅可用還原點，並按需要做 [CLI logical dump](https://supabase.com/docs/reference/cli/supabase-db-dump)。Supabase 文件指出資料庫備份唔包括 Storage 物件本身，檔案要另外備份。

合併到 `main` 或部署正式站之前：

1. 由專案擁有人核實最新可用還原點，同埋喺正式站下載一次帳戶 JSON；將檔案保存在安全位置。
2. 用現有帳戶喺 Netlify／Vercel 唯讀 preview 測試舊客戶、舊交易、收支、庫存同登入。要測試新增／修改流程，仍需隔離 Supabase staging 專案；預覽版會攔截寫入正式庫嘅請求。
3. 確認後先合併／正式部署。若需要回退，回退前端 commit；今次冇資料庫 migration 要回退。
